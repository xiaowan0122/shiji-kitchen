# 食记 Kitchen 产品需求文档（PRD）

**版本：** V1.0
**项目类型：** 微信原生小程序
**产品定位：** 个人菜谱管理 + 家庭厨房协作
**目标用户：** 1 人个人空间 / 3～5 人家庭共享
**云服务：** 腾讯云 CloudBase 国内站
**成本目标：** 0 元优先
**开发工具：** Codex
**核对日期：** 2026-11-20（本文档内所有数据/政策均以官方文档为来源并另行标注，见 COST_CONTROL.md）

# 1. 产品概述

## 1.1 产品定位

食记 Kitchen 是一个帮助个人与家庭管理和记录日常饮食的全流程工具，覆盖“菜谱 → 规划/点菜 → 购物清单 → 采购入库 → 烹饪 → 库存消耗 → 成本营养结算 → 日历/排行榜”的闭环。

产品由两类空间组成：
1. **个人空间**：只属于自己，管理自己的菜谱、做饭记录、饮食计划、成本与营养数据。
2. **家庭空间**：3～5 名家庭成员共同维护菜谱、饮食计划、购物清单、冰箱库存与家庭烹饪记录。

个人空间与家庭空间相互隔离；用户可以把个人菜谱“复制”进家庭空间，实现有限共享。

## 1.2 核心原则

- 数据以云端为准，多设备自动同步。
- 图片统一云端保存且按空间隔离。
- 个人数据与家庭数据严格隔离。
- 能通过普通代码计算的功能不调用 AI。
- 优先使用免费云资源，成本目标 0 元。
- 不做公开社区，不做复杂运营后台。

# 2. 用户与权限

## 2.1 用户

- 每个微信用户（以 openid 唯一标识）拥有一个**个人空间**。
- 同一用户可加入 0～N 个家庭空间。
- 家庭空间成员上限：5 人（V1.0）。

## 2.2 角色

| 角色 | 个人空间 | 家庭空间 |
| --- | --- | --- |
| Owner | 个人空间唯一所有者 | 创建家庭空间的人，唯一 Owner，不可转让给外部 |
| Admin | 不适用 | 可管理成员、编辑共享菜谱/库存 |
| Member | 不适用 | 可读写共享内容，不可管理成员 |

> 角色使用场景与权限矩阵详见 `docs/SECURITY.md`。

# 3. 功能模块

以下每个功能均按统一模板描述：**使用场景 / 页面入口 / 操作流程 / 数据字段 / 业务规则 / 异常情况 / 验收标准**。

## 模块 A：菜谱（创建、编辑、分类、收藏）

### A1. 使用场景
用户想记录一道菜的做法，可随时创建并保存菜谱；厨房操作时按步骤查看；根据分类（家常菜、汤、甜点等）与收藏快速检索。

### A2. 页面入口
- 首页「菜谱」入口。
- 底部 Tab「菜谱」列表页。
- 列表页右上角「＋/新建」。
- 菜谱详情页「编辑 / 收藏 / 删除」。
- 分类页「分类管理」。

### A3. 操作流程
1. 从菜谱列表进入新建或从详情进入编辑。
2. 填写基本信息：名称、封面图、分类、标签、描述、备注。
3. 添加食材（见模块 B）与步骤（见模块 A6）。
4. 填入份量基数、预估时间、难度、评分（见模块 L）。
5. 保存后自动同步到云端；手动/自动生成购物清单所需数据。

### A4. 数据字段（recipes 集合核心）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id / _id | string | 云数据库主键 |
| workspaceId | string | 所属空间（个人/家庭） |
| ownerOpenId | string | 创建者 |
| name | string | 菜名（必填） |
| categoryId | string | 分类 |
| tags | string[] | 标签 |
| coverFileId | string | 封面图云存储文件 id |
| imageFileIds | string[] | 步骤/相册图片 |
| servings | number | 基准份量（人数） |
| prepTime / cookTime / totalTimeMin | number | 时间（分钟） |
| difficulty | number(1-5) | 难度 |
| ingredientsRef | object[] | 食材（见模块 B） |
| steps | object[] | 步骤（见 A6） |
| nutrition | object | 营养汇总（见模块 F） |
| cost | object | 成本汇总（见模块 E） |
| rating | object | 评分（见模块 L） |
| isFavorite | bool | 收藏标记（个人视图） |
| status | enumerated | active / archived |
| createdBy / updatedBy | string | 审计 |
| createdAt / updatedAt | Date | 时间戳 |
| deleted | bool | 软删除 |

### A5. 业务规则
- 菜名必填；个人空间菜谱仅本人可见；家庭空间菜谱所有成员可见。
- 删除采用软删除，回收站可恢复（见模块 N/BACKUP）。
- 个人菜谱“复制到家庭”生成新文档，与原菜谱无关联（避免越权写原文档）。
- 收藏是个人视图属性，家庭空间内每名成员可各自收藏。

### A6. 详细操作步骤
- steps 元素：`{ seq, description, imageFileId?, timerMin? }`。
- 支持长文本、有序编号、单步配图；步骤可在编辑时拖拽排序。
- 验收：步骤顺序稳定；编辑后详情页与购物清单按最新内容渲染。

### A7. 异常情况
- 无网络：进入离线缓存模式，可编辑暂存，联网后自动上传（见 SYNC_DESIGN）。
- 封面图过大：自动压缩后上传（见 STORAGE_DESIGN）。
- 并发编辑：同一空间多人同时编辑同一菜谱，采取“最后写入为准”+ 版本号校验，冲突时提示用户。

### A8. 验收标准
- 能创建、编辑、删除、恢复、收藏、取消收藏菜谱。
- 分类与标签可维护；列表支持按名称/分类/标签/收藏筛选。
- 删除后列表不再出现，可进入回收站恢复。
- 数据在个人/家庭空间之间正确隔离，越权访问返回拒绝。

## 模块 B：食材与配料管理

### B1. 使用场景
菜谱需要记录每一种食材的用量、单位与可选项；同一食材在不同菜谱间复用定义，便于份量缩放与购物清单聚合。

### B2. 页面入口
- 菜谱编辑页内的「食材」编辑区。
- 「食材库」管理页（个人/家庭空间的统一食材字典）。

### B3. 操作流程
1. 在菜谱编辑中添加一条食材：选择或新建食材。
2. 填写用量、单位、是否可缺、是否属于购物清单项、提示（如“切片”）。
3. 保存后关联到菜谱。

### B4. 数据字段
- ingredients 集合：`{ _id, workspaceId, name, aliases, defaultUnit, category?, nutritionPerUnit?, pricePerUnit?, icon? }`。
- 菜谱内引用（recipes.ingredientsRef）：`{ ingredientId?, nameSnapshot, amount, unit, optional, isPurchase, note, unitId? }`。

### B5. 业务规则
- 用量 > 0；单位必须可换算（见模块 C）。
- 同一食材在个人空间与家庭空间各自维护字典，避免跨空间污染。
- 菜谱引用使用“名称快照 + ingredientId”双字段：即使食材字典改名，历史菜谱仍可显示原名。

### B6. 异常情况
- 单位不存在或不可换算：前端在保存时拦截并提示；购物清单生成失败时列出不可聚合项让用户手动处理。
- 食材被删除但被菜谱引用：仅允许软删除，保留名称快照。

### B7. 验收标准
- 可新增/修改/合并食材；菜谱能看到被引用食材的最新默认单位换算。
- 删除食材不影响已有菜谱显示与购物清单。

## 模块 C：份量自动缩放

### C1. 使用场景
原菜谱按 4 人份写，今天只做 2 人份或招待 8 人时，自动把每种食材用量与步骤时间按比例换算。

### C2. 页面入口
- 菜谱详情页顶部的「份量」选择器。

### C3. 操作流程
1. 查看菜谱详情，修改目标份量（人数）。
2. 前端按 `缩放系数 = 目标份量 / 基准份量` 换算所有食材用量。
3. 步骤时间按用户选择是否等比缩放（默认仅食材缩放，时间不强制缩放，因烹饪常非线性）。

### C4. 业务规则
- 食材换算 = 原始用量 × 系数，单位跟随（克、毫升等线性单位）。
- 对“个/枚”等不可小数单位，允许显示到 1 位小数并给出四舍五入说明；用户可手动覆盖单项。
- 目标份量必须 ≥1；基准份量 ≥1。
- 缩放系数缓存于前端，不写入数据库（详情页临时视图）。

### C5. 异常情况
- 某食材用量缺失或单位未知：该食材不缩放并高亮提示。
- 极端系数（>10 或 <0.1）：前端仍可计算，但给出提示防误操作。

### C6. 验收标准
- 4→2 人份时所有线性单位食材用量正确减半。
- 缩放不影响数据库中的原始值；返回默认份量时恢复原值。

## 模块 D：食材价格与菜品成本

### D1. 使用场景
记录买菜价格，估算每道菜成本与人均成本，帮助控制家庭饮食预算。

### D2. 页面入口
- 食材详情页「价格记录」。
- 菜谱详情页底部「成本」卡片。

### D3. 操作流程
1. 在食材价格记录中新增采购价：价格、数量、单位、日期、来源（超市/菜市场）。
2. 云函数或前端按最新价/移动平均计算单价。
3. 菜谱成本 = Σ(各食材用量 × 单价)，得出总成本与“人均成本 = 总成本 / 份量”。

### D4. 数据字段（ingredient_prices 集合）
`{ _id, workspaceId, ingredientId, unit, price, quantity, date, source, createdBy, createdAt }`

### D5. 业务规则
- 成本只做估算，界面需注明“估算值”。
- 默认取该食材最近一次有效价格；提供“最近一次 / 近7日均价”两种模式（V1.0 先实现最近一次）。
- 单位不一致时先换算为食材默认单位再算价。
- 家庭空间价格所有成员可见、可记。

### D6. 异常情况
- 食材无价格记录：成本显示“—”，不阻塞其他功能。
- 价格缺失单位：拒绝保存，提示补全。

### D7. 验收标准
- 录入价格后菜谱成本正确累加并显示人均成本。
- 无价格食材被明确标注为“未计价”，不与 0 混淆。

## 模块 E：热量与营养计算

### E1. 使用场景
关注热量/蛋白质/碳水/脂肪的用户希望看到每道菜及每日饮食的营养汇总。

### E2. 页面入口
- 菜谱详情页「营养」卡片。
- 饮食计划/日历页的每日营养汇总。

### E3. 操作流程
1. 每个食材维护/选择营养基准（每 100g 或每单位的热量、蛋白质、碳水、脂肪）。
2. 菜谱营养 = Σ(用量折合 × 食材营养基准)。
3. 按份量缩放后除以份量得到“每人每份营养”。

### E4. 业务规则
- V1.0 采用静态营养字典（预置常见食材），不做 AI 识别。
- 缺失营养数据的食材不纳入汇总并列出“待补充”。
- 单位先换算为质量（克）再计算；非质量单位需配置密度/换算。

### E5. 异常情况
- 营养字典缺失：显示“部分食材无营养数据”，不报错。
- 换算单位缺失：该食材跳过营养汇总。

### E6. 验收标准
- 营养汇总 = 各食材之和（误差允许 ±5% 的舍入说明）。
- 每日营养汇总按当日饮食计划正确累加。

## 模块 F：饮食计划与点菜

### F1. 使用场景
家庭成员（尤其是家庭空间）提前规划未来几天的三餐，别人可见；孩子/成员可“点菜”，指定某天想做哪道菜。

### F2. 页面入口
- Tab「计划」：周视图/列表。
- 菜谱详情页「加入计划」。
- 每日卡片「点菜」入口。

### F3. 操作流程
1. 选择日期（支持多日/周维度）。
2. 为“早餐/午餐/晚餐/加餐”选择一个菜谱或“自定义项”。
3. 提交后写入饮食计划；其他端实时同步。
4. 点菜：非 Owner 成员给某天指定菜谱并附留言，Owner/Admin 可采纳或忽略。

### F4. 数据字段
- meal_plans：`{ _id, workspaceId, startDate, endDate, createdBy, createdAt }`。
- meal_plan_items：`{ _id, planId, workspaceId, date, mealType, recipeId?, recipeNameSnapshot?, note, votes?, status, requestedBy?, createdBy }`。

### F5. 业务规则
- 每个 `(日期, 餐次)` 只允许一个正式项；点菜为请求态，采纳后覆盖正式项。
- 饮食计划完成后可“一键生成购物清单”（见模块 G）。
- 个人空间只有本人生效；家庭空间全员可见。

### F6. 异常情况
- 选中菜谱在家庭成员被移除后不可见：计划项保留名称快照但标记“来源菜谱不可访问”。
- 同一餐次并发写入：以最后提交为准并记录冲突。

### F7. 验收标准
- 能按天/餐次新增、修改、删除计划项；点菜请求与采纳流程可用。
- 按计划日期范围能聚合出菜品清单用于生成购物清单。

## 模块 G：自动生成购物清单

### G1. 使用场景
确定未来几天吃什么后，一键把所需食材汇总去重，生成采购清单，避免重复购买。

### G2. 页面入口
- Tab「购物清单」。
- 饮食计划页「一键生成」。

### G3. 操作流程
1. 选择日期范围（默认计划周期）。
2. 系统汇总所选菜谱的所有 `isPurchase=true` 食材。
3. 相同食材按单位聚合用量；生成清单条目。
4. 可手动增删条目、勾选“已买”。

### G4. 数据字段
- shopping_lists：`{ _id, workspaceId, name, dateRange?, status, createdBy, createdAt }`。
- shopping_items：`{ _id, listId, workspaceId, ingredientId?, name, unit, amountPlus? (拼接), checked, addedBy }`。

### G5. 业务规则
- 仅聚合标记为“购买”的食材；未购买项进入清单。
- 同一食材合并用量（如“鸡蛋”多道菜累加），单位不一致时先换算。
- 勾选“已买”后可联动扣减冰箱库存（见模块 H，作为可选联动，V1.1 默认手动确认）。
- 清单按空间隔离；删除清单为软删除。

### G6. 异常情况
- 食材无可换算单位：该食材拆分为多条或用“数量+单位”文本拼接，提示用户核对。
- 无计划数据：提示先生成计划；提供“从菜谱直接加入”入口。

### G7. 验收标准
- 多道菜能正确聚合去重并汇总用量。
- 手动增删、勾选状态实时同步到其他成员端。

## 模块 H：冰箱库存、采购批次与保质期

### H1. 使用场景
记录冰箱/储物里有什么、各批次买了多少、何时过期，避免浪费和误用过期食品。

### H2. 页面入口
- Tab「库存」：当前库存、临近过期提醒、批次明细。
- 采购页选择“入库到库存”。

### H3. 操作流程
1. 新增采购批次：食材、数量、单位、单价、采购日期、保质期（bestBefore）。
2. 库存面板展示汇总数量与过期状态（正常 / 临期 / 过期）。
3. 烹饪/消耗时扣减批次数量；支持“按批次先进先出 FIFO”扣减。

### H4. 数据字段
- pantry_items：`{ _id, workspaceId, ingredientId?, name, totalQty, unit, minStock?, location?, reminderDays, updatedAt }`。
- pantry_lots：`{ _id, pantryItemId?, workspaceId, ingredientId, batchNo, qty, unit, unitPrice, purchaseDate, bestBefore, source, createdBy }`。
- inventory_transactions：`{ _id, workspaceId, pantryItemId, lotId?, type(purchase/consume/adjust/expire), qty, unit, beforeQty?, afterQty?, refType?, refId?, operator, createdAt }`。

### H5. 业务规则
- 库存以批次（lot）为最小追溯单位；pantry_items 做汇总视图。
- 每次增减都写 inventory_transactions 流水，保证可审计与可反推。
- 过期判定以 bestBefore 与“今日”比较；临期提醒天数可按食材配置（默认 3 天）。
- 消耗默认先进先出（FIFO），库内记录每批剩余。
- 采购入库可选引用购物清单条目，自动勾选“已买”。

### H6. 异常情况
- 扣减数量大于该批剩余：默认 FIFO 依次从多批次扣，若总量不足则拒绝并提示。
- 过期批次：允许“报损”操作生成 expire 流水并移出可用库存。

### H7. 验收标准
- 采购入库后库存汇总与批次明细正确。
- FIFO 扣减、报损、临期提醒在“今日”语义下正确（支持设定测试日期）。
- 全部库存变化都有流水，可还原任意时间点库存。

## 模块 I：烹饪记录与美食相册

### I1. 使用场景
记录某天实际做了哪道菜、成品照片、主观评分，形成家庭相册与个人“做过”历史。

### I2. 页面入口
- 菜谱详情页「记录一次」。
- Tab「相册」。

### I3. 操作流程
1. 烹饪完成后选择菜谱（或自定义），上传成品照片。
2. 填写评分（1-5 星，可选）、备注、时间。
3. 保存为 cooking_records 并同步；照片进入相册流。

### I4. 数据字段（cooking_records）
`{ _id, workspaceId, recipeId?, recipeNameSnapshot, photos[] (fileId), rating?, note?, date, createdBy, createdAt }`

### I5. 业务规则
- 照片上传前压缩；访问受空间权限控制。
- 记录一经删除为软删除。

### I6. 异常情况
- 图片上传失败：记录仍可保存（图置空），提示可后补。

### I7. 验收标准
- 能记录、上传照片、评分并出现在相册与日历。

## 模块 J：日历记录

### J1. 使用场景
以日历形式回看“哪天吃了什么、哪天做了什么”，便于周计划与打卡。

### J2. 页面入口
- Tab「日历」。

### J3. 操作流程
1. 月/周视图点击日期查看当天饮食计划与烹饪记录。
2. 点击空白处可快速新增计划项或记录。

### J4. 业务规则
- 日历数据 = meal_plan_items + cooking_records 聚合。
- 个人空间显示个人数据；家庭空间显示全员数据并标记操作人。

### J5. 验收标准
- 日历正确聚合计划与烹饪记录，切换月份加载对应数据。

## 模块 K：每周/每月/每年排行榜

### K1. 使用场景
统计家庭成员的参与度与个人做饭趣味性（做了几道菜、评分最高、最常做的菜）。

### K2. 页面入口
- Tab「排行」。

### K3. 操作流程
1. 选择周期（周/月/年）与指标。
2. 后端聚合 cooking_records / 评分生成榜单。

### K4. 业务规则
- 榜单为家庭空间功能；指标：做菜次数、平均评分、收藏数等。
- 仅统计有效（未软删除）记录。

### K5. 验收标准
- 按周期正确统计并排序；数据随新记录同步刷新。

## 模块 L：菜品等级与评分

### L1. 使用场景
对菜谱和烹饪结果给出 1-5 星评价，沉淀“家人都爱”的菜。

### L2. 页面入口
- 菜谱详情页评分区；烹饪记录中的评分。

### L3. 业务规则
- 家庭空间内每人可对同一菜谱评一次分，取平均；改动即重算。
- 评分与等级（关联榜单）数据存 `recipes.rating` 与 `cooking_records.rating`。

### L4. 验收标准
- 一成员评分生效并正确影响平均分与排行。

## 模块 M：个人与家庭数据自动同步

### M1. 使用场景
家里多人、多设备看到的数据一致；断网后重连自动补齐。

### M2. 实现方案
优先使用 CloudBase 数据库 `collection.watch()` 实时监听 + 云端写入，辅以本地缓存与断点续传；网络中断后重新建立监听并拉取增量。完整权衡与验证清单见 `docs/SYNC_DESIGN.md`（实时额度及相关 API 需联网核实）。

### M3. 验收标准
- 写操作落库后其余在线设备 ≤ 数秒内可见。
- 断网期间本地修改本地保存，恢复后自动合并/补传，不丢数据、不重复创建主键。

## 模块 N：数据备份与恢复

### N1. 使用场景
误删/换机后能恢复数据。

### N2. 方案
- 云端作为主数据源；另提供“一键导出 JSON”备份与“导入恢复”。
- 回收站软删除保留期：菜谱 30 天、计划/清单 15 天。
- 具体策略与限制见 `docs/BACKUP_RESTORE.md`。

### N3. 验收标准
- 能导出全空间数据并导入到同空间恢复；导入前自动校验 schema 版本。
