# 食记 Kitchen Codex 分阶段开发计划

核对日期：2026-11-20

# 0. 总原则

- 一次只做一个阶段；每阶段结束输出验收报告并**停止，等待用户确认**，不得自动进入下一阶段。
- 每阶段遵守 AGENTS.md 约束。
- 涉及联网核实的项，在本机网络恢复后作为对应阶段的第一任务完成，并回写 DECISIONS.md。

# 1. 阶段0：项目初始化与技术文档（当前）

目标：建立目录、环境检查、构建全部设计文档。

任务：
1. 检查环境（Node、npm、Git、微信开发者工具、当前目录、Git 仓库状态）。
2. 建立项目目录结构（miniprogram、cloudfunctions、docs、scripts）。
3. 创建 AGENTS.md、README.md、.gitignore。
4. 创建 docs 全部文档（PRD、ARCHITECTURE、DATABASE、API、SECURITY、SYNC_DESIGN、STORAGE_DESIGN、COST_CONTROL、BACKUP_RESTORE、TEST_PLAN、CODEX_PLAN、OPEN_SOURCE_REFERENCES、DECISIONS、ENVIRONMENT）。
5. 分析开源项目并记录许可证与借鉴限制（OPEN_SOURCE_REFERENCES.md）。
6. 完善 PRD、数据库、同步、安全、成本、计划。

验收标准：
- 目录与文档实际落地，PRD 每个功能含场景/入口/流程/字段/规则/异常/验收。
- 数据库 16 集合含字段、索引、关系、权限。
- 同步与成本文档明确标注待联网核实项，不编造。
- 环境检查结论记录在 ENVIRONMENT.md。

测试要求：本阶段以文档评审为主；单元测试自阶段1起建立。

# 2. 阶段1：小程序 UI 框架

任务：
1. 初始化微信小程序工程（project.config.json、app.ts/json/wxss、sitemap）。
2. 建立全局主题样式、组件库基础（份量选择器、标签、步进器、图片、底部导航）。
3. 实现主导航（首页、菜谱、计划、购物清单、库存、我的）与空态骨架。
4. 建立 services/utils/types 分层与路由。

验收标准：
- 主流程页面可打开、可导航，布局在常见机型不溢出。
- UI 框架可运行（微信开发者工具中），无控制台报错。

测试要求：开发者工具预览 + 至少一种屏幕尺寸截图核对；无布局溢出。

# 3. 阶段2：CloudBase 接入

任务：
1. 创建/确认免费云环境（**未联网/未确认前不创建**，需用户提供 AppID 与授权）。
2. wx.cloud.init、初始化数据库集合与安全规则。
3. login 云函数（openid 登录 + 个人空间初始化）。
4. 本地缓存与网络封装。
5. 核实并完成 SYNC_DESIGN 的联网核实项第一版。

验收标准：
- 能登录并初始化个人空间；数据入库。
- 集合与安全规则按 DATABASE/SECURITY 落地。

测试要求：云函数单测 + 开发者工具联调登录/读写。

# 4. 阶段3：个人空间与家庭空间

任务：
1. workspace / workspace_members / invite 云函数。
2. 个人空间数据管理；创建家庭空间。
3. 邀请码生成、接受、撤销；角色权限（Owner/Admin/Member）校验工具。
4. 成员移除与越权测试。

验收标准：
- 个人/家庭数据隔离；越权返回 403。
- 邀请码一次性、过期、满员处理正确。

测试要求：安全用例（越权矩阵、邀请码并发）。

# 5. 阶段4：实时同步与图片管理

任务：
1. 按 SYNC_DESIGN 最终结论实现 watch / 增量对账 / 离线队列。
2. 图片压缩上传、media_assets、临时链接鉴权。
3. 断网写→重连对账。

验收标准：
- 多端在线数秒内一致；断网恢复后不丢不重。
- 图片无鉴权不可访问。

测试要求：同步集成测试 + 图片权限用例。

# 6. 阶段5：菜谱管理

任务：
1. 菜谱列表/详情/编辑（含食材与步骤）。
2. 分类、标签、收藏、软删除/恢复、复制到家庭。

验收标准：按 PRD 模块 A 验收，含筛选、复制、隔离。
测试要求：单元（构造/计算）+ 端到端。

# 7. 阶段6：成本与营养

任务：
1. 食材字典与单位换算。
2. ingredient_prices 价格记录与成本计算。
3. 营养基准与聚合。
4. 份量缩放接入各视图。

验收标准：PRD 模块 B/C/D/E 验收，缩放/成本/营养正确。
测试要求：纯函数单测（换算、缩放、聚合、缺失处理）。

# 8. 阶段7：饮食计划与购物清单

任务：
1. meal_plans / meal_plan_items，周视图与点菜采纳。
2. 购物清单聚合生成、手动增删、勾选。

验收标准：PRD 模块 F/G 验收。
测试要求：聚合去重 + 并发写。

# 9. 阶段8：库存、烹饪记录、日历与排行榜

任务：
1. 库存、批次、FIFO、流水、临期提醒。
2. cooking_records、相册、日历聚合。
3. 周/月/年排行榜。

验收标准：PRD 模块 H/I/J/K 验收。
测试要求：FIFO/流水/排行单测 + 日历聚合。

# 10. 阶段9：备份、测试与体验版部署

任务：
1. backup 导出/导入与回收站清理。
2. 完整回归 + 安全用例 + 隐私合规。
3. 上传体验版并走微信审核相关流程（如需正式发布由用户发起）。

验收标准：
- 备份恢复一致、幂等。
- 全量回归通过；体验版可安装体验。

测试要求：完整回归与真机测试报告。

# 11. 依赖与先后

- 阶段0→1（UI）→2（云接入）→3（空间）→4（同步/图片）→5（菜谱）→6（成本营养）→7（计划清单）→8（库存记录日历排行）→9（备份发布）。
- 阶段2、4 强烈依赖联网核实；若网络受限，先把可离线部分推进并保留核实为阶段2/4之首。

# 12. 风险登记

- 免费额度不足或政策变化：按 COST_CONTROL 优化，不擅自付费。
- watch 额度/权限不满足：退化为增量对账 + 轮询（SYNC_DESIGN 备选）。
- 安全规则不支持“成员集合判断”：改用云函数统一鉴权。
- 三个开源项目许可证限制复制，仅借鉴设计（见 OPEN_SOURCE_REFERENCES.md）。
