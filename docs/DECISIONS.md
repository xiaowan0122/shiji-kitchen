# 食记 Kitchen 技术决策记录（ADR）

核对日期：2026-11-20
状态说明：`已定`=已锁定；`待核实`=需联网后按官方文档确认，确认前不得落地为最终事实。

# ADR-001 技术栈

- 状态：已定。
- 决定：微信原生小程序 + TypeScript + WXML + WXSS；CloudBase 国内站（文档数据库、云函数、云存储、微信登录）；V1.0 不接付费 AI。
- 理由：满足家庭小型协作、多端同步、0 元目标；技术栈已由用户确定，禁止更改。
- 影响：不使用独立后端/数据库/Redis/Docker。

# ADR-002 统一 workspaceId 数据隔离

- 状态：已定。
- 决定：个人与家庭统一用 `workspaceId` 作为隔离键；个人空间为 `type=personal`，家庭为 `type=family`。
- 理由：单一隔离模型，权限判断与服务端校验统一，简化多空间归属。
- 影响：所有业务集合必须携带 workspaceId；所有查询带该前缀。

# ADR-003 数据访问方式（云函数 vs 直连）

- 状态：已定。
- 决定：重要写操作一律走云函数并在服务端校验角色/空间；只读集合可按集合明确安全规则开放客户端读取。
- 理由：数据库规则难以表达复杂角色逻辑；云函数可统一鉴权与聚合。
- 影响：见 SECURITY.md；逐集合定规则，不偷懒“一律仅创建者”。

# ADR-004 同步方案

- 状态：待核实（设计采取 A 为主 + B/C 兜底）。
- 决定：首选 CloudBase `collection.watch()` 实时监听；断网/失败退化为 sync_events 增量对账或轮询。
- 理由：原生支持、实时性好；需官方核实额度与权限，未核实前不锁定。
- 影响：SYNC_DESIGN.md 的执行与阶段4首个任务为核实 + 最小验证。

# ADR-005 软删除与数据完整性

- 状态：已定。
- 决定：业务删除走 `deleted` 软删除 + 回收站；关键多集合写入用事务。
- 理由：防误删、可审计、可恢复。
- 影响：所有查询默认过滤 deleted；字段变更走迁移脚本。

# ADR-006 图片策略

- 状态：已定。
- 决定：图片入 CloudBase 存储（按 workspaceId 分目录），客户端压缩、列表用缩略图，展示用云函数签发临时链接。
- 理由：控制成本与流量，避免无鉴权扩散。
- 影响：STORAGE_DESIGN.md。

# ADR-007 开源复用边界

- 状态：已定。
- 决定：仅借鉴领域概念与交互思路，不复制三项目源码；Mealie/Tandoor（AGPL/Commons Clause）尤其不搬代码，Grocy（MIT）也按设计借鉴。
- 理由：本项目闭源定位 + 许可证合规。
- 影响：OPEN_SOURCE_REFERENCES.md；所有“借鉴”算法自研实现。

# ADR-008 成本策略

- 状态：待核实。
- 决定：目标 0 元，优先免费额度；通过压缩、缩略图、watch 代替轮询、云函数聚合、分页降低用量。
- 影响：超出免费额度时先优化降级，不擅自付费。额度待联网核实（COST_CONTROL.md）。
