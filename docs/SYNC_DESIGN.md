# 食记 Kitchen 自动同步设计

核对日期：2026-11-20

# 0. 重要声明（必须先读）

本文件的结论基于对 CloudBase 官方能力的了解（设计方案），但**本机当前网络受限**（见 docs/ENVIRONMENT.md），无法直接访问腾讯云与微信官方文档进行实测核实。凡标注【需核实】的条目，必须在联网后对照官方文档确认，未核实前不得当作已定事实落地。禁止把估算写成保证。

# 1. 目标

- 多设备、多成员实时看到一致数据。
- 断网期间本地修改不丢失，恢复后自动补齐。
- 数据以云端为准，客户端为缓存视图。
- 成本优先，尽量复用免费实时额度。

# 2. 候选方案

## 方案 A：CloudBase collection.watch() 实时监听（首选）

- 客户端对目标集合执行 `db.collection(...).where(条件).watch(...)`，收到该集合变更事件后刷新。
- 优点：微信原生小程序内置 API，改动小、实时性好。
- 关键点【需核实】：
  - 小程序端实时监听 API `collection.watch` 是否可用（基础库版本）。
  - watch 的权限要求（是否要求登录、对安全规则的依赖）。
  - 实时连接额度与每个环境的连接数限制；超过是否降级或收费。
  - 连接释放方式：`watcher.close()`；页面卸载/小程序切后台时如何管理连接以省额度。
  - 监听失败、网络中断后的自动重连机制与数据一致性。

## 方案 B：云函数事件 + sync_events 增量（候选）

- 云函数每次写操作写入 `sync_events`；客户端启动/重连时拉取 `createdAt > 本地cursor` 的增量事件重放。
- 优点：可控、可对账、断点续传简单，不依赖实时连接额度。
- 缺点：非“真实时”（需轮询或与 A 结合），且写两处（业务表 + 事件表）需事务保证。

## 方案 C：客户端轮询

- 定时拉取（如每 30s）按 updatedAt 增量。
- 优点：简单、稳定、无额外额度。
- 缺点：实时性差、请求量大（成本/配额），仅作兜底。

# 3. 建议的落地方案

采用**方案 A 为主 + 方案 B 兜底/对账**的组合，且前提是联网核实后方案 A 的额度与权限满足需求：

1. 在线时：`watch()` 监听各业务集合（按 workspaceId 过滤），变更即刷新本地缓存。
2. 断网/监听失败：退化为方案 B 增量拉取（sync_events）或方案 C 轮询；恢复后再重新建立 watch 并做一次增量对账消除窗口。
3. 写操作：先落云端（云函数），watch 事件驱动其他设备；本地乐观更新 UI，云端失败回滚提示。

> 决策依赖核实结果：若方案 A 免费额度不足或权限限制过大，则以方案 B + C 为主、A 辅助。该决策最终结论记录在 docs/DECISIONS.md。

# 4. 数据一致性模型

- 文档级冲突：`updatedAt` + `version` 校验，采用“最后写入为准”。
- 删除：软删除，事件/对账跳过 `deleted=true`。
- 主键：客户端可用 `wx.cloud` 生成或由云端 `_id` 保证，重复提交用幂等键（`clientOpId`）防重复。
- 离线写：本地暂存队列，重连同放；每项带 clientOpId，云端幂等去重。

# 5. 增量对账算法

```text
本地 cursor = 上一次同步的同步水位（如 max(updatedAt, version)）
重连后：
  1) 拉增量 sync_events where workspaceId==X and createdAt > cursor
  2) 逐条重放/合并到本地
  3) 更新 cursor
  4) 重建 watch()
```

# 6. 实时连接生命周期

- 进入页面按需 watch；离开销毁 `watcher.close()`。
- 小程序切后台：不活跃页面暂停订阅，回前台恢复并对账【需核实平台行为】。
- 全局限制连接数【需核实】，必要时做“单实例 watch + 事件广播到本地”以减少连接。

# 7. 数据权限与 watch

- watch 只订阅当前用户可访问空间的数据，规则与 SECURITY.md 一致。
- 【需核实】watch 是否会因为安全规则的查询未命中集合而报错或静默；务必用最小数据验证权限路径。

# 8. 失败与恢复矩阵

| 场景 | 处理 |
| --- | --- |
| 首次安装 | 云端全量拉取 + 建立本地缓存 |
| 断网写 | 本地暂存 + 红点提示待同步 |
| 断网读 | 读本地缓存（离线可用） |
| 重连 | 增量对账 + 重建 watch |
| watch 额度超限 | 降级为轮询，并提示“实时同步暂不可用” |
| 并发冲突 | 版本校验，后写覆盖，前端提示 |

# 9. 待联网核实清单

1. 小程序端 `collection.watch` 可用性与最小基础库版本。
2. watch 对安全规则的要求与登录要求。
3. 免费实时连接数/额度及超额计费规则。
4. watcher.close 与切后台行为。
5. 云函数写库后客户端 watch 是否收到（事件传播）。
6. 是否存在“实时数据推送”独立产品及价格（若 watch 不足的替代）。
7. sync_events 增量查询在免费读次数下的成本量级。
