# 食记 Kitchen 产品需求文档（PRD）

**版本：** V1.0
**项目类型：** 微信原生小程序
**产品定位：** 个人菜谱管理 + 家庭厨房协作
**目标用户：** 1～5人家庭
**云服务：** 腾讯云 CloudBase 国内站
**成本目标：** 0元优先
**开发工具：** Codex

# 1. 产品概述

## 1.1 产品定位

食记 Kitchen 是一个用于记录菜谱、管理食材、规划每日饮食、计算烹饪成本、管理家庭库存的私人厨房管理工具。

产品由两个独立空间组成：

1. 个人空间：管理自己的菜谱、做饭记录、饮食计划、成本和营养数据。
2. 家庭空间：家庭成员共同管理菜谱、饮食计划、购物清单、冰箱库存和家庭烹饪记录。

个人空间和家庭空间相互隔离，允许用户将个人菜谱复制到家庭空间。

## 1.2 产品目标

第一阶段需要实现完整的厨房管理闭环：

菜谱创建 → 菜谱规划 → 点菜 → 生成购物清单 → 采购入库 → 烹饪 → 库存消耗 → 记录成本与营养 → 日历记录 → 排行榜统计。

## 1.3 核心设计原则

- 所有数据以云端为准。
- 多设备自动同步。
- 图片统一云端保存。
- 个人数据与家庭数据严格隔离。
- 能通过普通代码计算的功能不调用AI。
- 优先使用免费云资源。
- 不依赖付费第三方API。
- 不做公开社区。
- 不设计复杂运营后台。

# 2. 用户及权限体系

## 2.1 用户类型

### 个人用户

首次登录自动创建个人空间。

可以：

- 创建菜谱。
- 编辑菜谱。
- 上传图片。
- 管理食材。
- 管理个人库存。
- 创建个人饮食计划。
- 记录做饭历史。
- 查看个人统计和排行榜。

### 家庭用户

家庭创建者可以创建家庭空间并邀请其他成员。

家庭成员共享：

- 菜谱。
- 饮食计划。
- 购物清单。
- 冰箱库存。
- 做饭记录。
- 家庭统计。

V1.0 每个用户支持一个个人空间和一个家庭空间，家庭最多5名成员。

## 2.2 角色权限

| 操作               | Owner | Admin | Member |
| ------------------ | ----- | ----- | ------ |
| 查看家庭数据       | 是    | 是    | 是     |
| 创建菜谱           | 是    | 是    | 是     |
| 编辑自己创建的菜谱 | 是    | 是    | 是     |
| 编辑他人菜谱       | 是    | 是    | 否     |
| 创建饮食计划       | 是    | 是    | 是     |
| 管理库存           | 是    | 是    | 是     |
| 邀请成员           | 是    | 是    | 否     |
| 移除成员           | 是    | 是    | 否     |
| 修改家庭信息       | 是    | 是    | 否     |
| 解散家庭           | 是    | 否    | 否     |

家庭成员被移除后，必须立即失去家庭空间的访问权限。

## 2.3 家庭邀请

实现：

- 创建家庭邀请码。
- 邀请码有效期24小时。
- 邀请码最多使用4次。
- 家庭人数达到5人后禁止继续加入。
- 加入前展示家庭名称。
- 加入成功后自动切换至家庭空间。
- 已加入成员不能重复加入。

邀请码不能直接保存明文，数据库存储邀请码哈希。

# 3. 菜谱管理模块

优先级：P0。

## 3.1 菜谱创建

支持手动创建菜谱。

基本信息：

| 字段     | 说明                           |
| -------- | ------------------------------ |
| 菜品名称 | 必填                           |
| 菜品封面 | 支持上传                       |
| 菜品分类 | 主食、荤菜、素菜、汤类、饮品等 |
| 菜品标签 | 家常菜、减脂、早餐等           |
| 适合人数 | 默认2人                        |
| 准备时间 | 分钟                           |
| 烹饪时间 | 分钟                           |
| 难度等级 | 简单、中等、困难               |
| 菜品描述 | 可选                           |
| 来源链接 | 可选                           |
| 制作备注 | 可选                           |

## 3.2 配料管理

每道菜可以添加多个食材。

每个配料包含：

- 食材名称。
- 用量。
- 单位。
- 单价。
- 食材成本。
- 是否可替代。
- 备注。

支持：

- g。
- kg。
- mg。
- ml。
- L。
- 个。
- 根。
- 片。
- 勺。
- 适量。

不同单位不能无条件转换。

例如：

- 1kg = 1000g。
- 1L = 1000ml。
- ml 转 g 必须有食材密度。
- 个转 g 必须有单个食材重量。

未知转换关系时，要求用户补充换算值。

## 3.3 烹饪步骤

每道菜支持多个步骤。

每一步包含：

- 步骤序号。
- 操作文字。
- 步骤图片。
- 预计耗时。
- 注意事项。

支持新增、删除、排序、编辑。

## 3.4 菜谱份量缩放

例如：

原菜谱：

- 2人份。
- 猪肉200g。
- 土豆300g。

改为4人份：

- 猪肉400g。
- 土豆600g。

自动重新计算配料数量、预计成本和营养数据。

用户可以手动修改缩放后的配料。

## 3.5 菜谱等级

采用1～5星评价。

| 等级  | 定义             |
| ----- | ---------------- |
| ★★★★★ | 非常满意，拿手菜 |
| ★★★★  | 比较满意         |
| ★★★   | 普通             |
| ★★    | 有待改进         |
| ★     | 不太成功         |

支持附加标签：

- 拿手菜。
- 家庭最爱。
- 快手菜。
- 待改进。
- 值得复做。

## 3.6 菜谱合集

支持用户创建自己的菜谱合集：

- 早餐合集。
- 工作日快手菜。
- 减脂餐。
- 家常菜。
- 节日菜谱。
- 家庭最爱。

同一道菜可以加入多个合集。

## 3.7 菜谱导入

V1.0：

- 手动录入。
- 从个人空间复制到家庭空间。
- 从JSON备份恢复。

V1.1：

- 输入网页URL。
- 解析网页中的Schema.org Recipe / JSON-LD。
- 自动提取菜名、配料、步骤、图片。
- 用户确认后保存。

网页导入失败时提供手动编辑入口。

不允许未经用户确认直接保存解析结果。

# 4. 成本计算模块

优先级：P0。

## 4.1 食材价格管理

每种食材可以记录采购价格。

例如：

| 食材   | 采购规格 | 价格 |
| ------ | -------- | ---- |
| 猪肉   | 500g     | ¥15  |
| 鸡蛋   | 10个     | ¥12  |
| 土豆   | 1000g    | ¥4   |
| 西红柿 | 500g     | ¥5   |

自动计算标准单位价格。

## 4.2 菜谱成本

公式：

食材成本 = 使用数量 × 单位价格

菜谱总成本 = 所有食材成本之和

单人份成本 = 菜谱总成本 ÷ 适用人数

对于没有价格记录的食材：

- 标记为未计价。
- 不允许默认当成0元。
- 提示用户补充价格。

## 4.3 历史成本

每次实际烹饪时保存成本快照。

历史记录必须保留：

- 食材名称。
- 实际用量。
- 当时单价。
- 单项成本。
- 总成本。
- 制作人数。

后续食材价格发生变化，不修改历史记录。

## 4.4 成本统计

支持：

- 单道菜成本。
- 单人份成本。
- 每日饮食成本。
- 每周成本。
- 每月成本。
- 每年成本。
- 家庭总消费。
- 不同菜品成本排行。

# 5. 营养管理模块

优先级：P0。

## 5.1 食材营养数据

每种食材记录每100g营养值：

- 热量 kcal。
- 蛋白质 g。
- 脂肪 g。
- 碳水化合物 g。
- 膳食纤维 g。
- 钠 mg。

允许用户补充或修改营养数据，并记录数据来源。

## 5.2 菜谱营养计算

营养总量：

每种食材营养值 × 食材重量 ÷ 100。

菜谱总营养为所有食材营养之和。

单人份营养 = 菜谱总营养 ÷ 制作人数。

如果某个食材没有营养数据：

- 显示部分统计。
- 标记营养数据不完整。
- 不得将未知值直接当成0。

## 5.3 营养统计

支持：

- 每道菜营养。
- 每日热量。
- 每周热量。
- 每月热量。
- 蛋白质、脂肪、碳水统计。

第一版只提供数据记录和统计，不提供医疗诊断或个性化医疗建议。

# 6. 饮食计划和点菜模块

优先级：P0。

## 6.1 日历计划

每一天支持：

- 早餐。
- 午餐。
- 晚餐。
- 加餐。

每个餐次可以添加多道菜。

## 6.2 家庭点菜

家庭成员可以提交想吃的菜品。

记录：

- 点菜成员。
- 菜品。
- 日期。
- 餐次。
- 人数。
- 备注。
- 状态。

状态：

- 待确认。
- 已确认。
- 已安排。
- 制作中。
- 已完成。
- 已取消。

这里的点菜是家庭内部饮食计划，不涉及支付或外卖交易。

## 6.3 菜单安排

家庭管理员或成员可以：

- 调整日期。
- 调整餐次。
- 增加菜品。
- 删除菜品。
- 指定制作人。
- 修改人数。

## 6.4 从计划生成购物清单

根据选定日期范围的饮食计划：

1. 提取菜谱食材。
2. 合并相同食材。
3. 统一可转换单位。
4. 计算所需总量。
5. 查询当前库存。
6. 允许用户选择是否扣除库存。
7. 生成购物清单。

不能自动把尚未采购的商品当成库存。

# 7. 购物清单模块

优先级：P0。

## 7.1 清单创建

支持：

- 手动添加。
- 根据菜谱生成。
- 根据一周计划生成。
- 根据库存低于阈值生成。

## 7.2 自动合并

例如：

红烧肉需要猪肉300g。

土豆炖牛肉需要猪肉200g。

购物清单合并为猪肉500g。

不能可靠转换的单位保持分开。

## 7.3 采购分类

按类别自动整理：

- 蔬菜。
- 水果。
- 肉类。
- 水产。
- 蛋奶。
- 调味品。
- 主食。
- 其他。

## 7.4 采购状态

- 待购买。
- 已购买。
- 暂不购买。
- 已入库。

勾选已购买后，可以选择将食材添加到冰箱库存。

# 8. 冰箱库存模块

优先级：P0。

借鉴Grocy的库存批次和流水设计。

## 8.1 库存管理

每种食材支持多批次。

例如：

猪肉：

- 第一批：500g，11月18日购买，11月21日到期。
- 第二批：1000g，11月19日购买，11月24日到期。

不能把两批食材简单合并后丢失各自的保质期。

## 8.2 库存字段

- 食材名称。
- 当前剩余数量。
- 单位。
- 购买日期。
- 保质期。
- 采购价格。
- 存放位置。
- 库存批次。
- 创建人。

## 8.3 库存流水

支持：

- 采购入库。
- 烹饪消耗。
- 手动调整。
- 过期报损。
- 丢弃。
- 退货。

所有库存变化都要生成流水。

禁止只修改当前数量而不保留历史记录。

## 8.4 库存提醒

进入小程序时检查：

- 已过期食材。
- 3天内到期食材。
- 7天内到期食材。
- 低库存食材。

V1.0 采用页面内提醒，不使用付费短信或复杂的后台定时任务。

# 9. 烹饪记录模块

优先级：P0。

每次实际做菜后生成一条记录。

内容：

- 菜谱。
- 制作日期。
- 制作人。
- 实际人数。
- 实际用料。
- 实际成本。
- 营养快照。
- 制作图片。
- 评分。
- 制作心得。
- 是否消耗库存。

支持从饮食计划直接进入制作记录。

完成烹饪时：

1. 保存实际使用量。
2. 计算实际成本。
3. 保存营养快照。
4. 根据用户确认情况扣减库存。
5. 写入日历。
6. 更新排行榜数据来源。

库存扣减和做饭记录需要保证一致性，失败时不得出现只扣库存、不生成记录的情况。

# 10. 日历模块

优先级：P0。

支持：

- 月视图。
- 周视图。
- 日详情。

日历标识：

- 蓝色：已有饮食计划。
- 绿色：已经完成烹饪。
- 橙色：存在未处理的点菜。
- 灰色：无记录。

点击日期展示：

- 早餐。
- 午餐。
- 晚餐。
- 加餐。
- 计划菜品。
- 实际制作菜品。
- 制作照片。
- 总成本。
- 总热量。

计划和实际烹饪必须分开记录。

# 11. 排行榜模块

优先级：P1。

支持：

- 周榜。
- 月榜。
- 年榜。

排行榜范围：

- 个人空间。
- 家庭空间。

排行榜类型：

1. 制作次数排行。
2. 平均评分排行。
3. 最受欢迎菜品。
4. 最低单人份成本。
5. 最高单人份成本。
6. 最常做菜品。

规则：

- 只统计已完成的烹饪记录。
- 未完成计划不计入。
- 平均评分必须显示评价数量。
- 成本比较必须只比较数据完整的菜品。
- 数据量不足时显示样本不足。
- 统计时间按照中国标准时间。

V1.0 使用数据库查询后在云函数中聚合，不部署独立统计服务器。

# 12. 图片管理

优先级：P0。

支持：

- 菜谱封面。
- 烹饪步骤图片。
- 实际成品照片。

要求：

- 上传前压缩。
- 单张图片限制1MB。
- 推荐300～500KB。
- 最长边建议1600px。
- 不上传RAW文件。

- 不长期保存临时下载URL。

# 16. 非功能要求

## 性能

- 列表分页，每页默认20条。
- 图片懒加载。
- 图片压缩。
- 首页优先加载核心信息。
- 不进行全库无条件查询。
- 不使用高频轮询。
- 不在每个页面重复建立实时监听。

## 安全

- 不在前端保存服务端密钥。
- 不相信客户端传入的用户身份。
- 所有重要写操作必须进行服务端权限验证。
- 家庭数据必须校验成员关系。
- 图片访问必须校验权限。
- 退出家庭后立即失去访问权限。

## 稳定性

- 云端数据作为最终数据源。
- 重要操作使用幂等请求ID。
- 库存更新使用事务或等效原子操作。
- 多设备编辑时进行版本冲突检查。
- 断网后显示缓存数据和离线状态。
- 网络恢复后重新同步。

## 成本

- 不启用真实AI。
- 不使用付费API。
- 不购买域名。
- 不创建独立管理后台。
- 不使用付费消息通知。
- 优先控制在CloudBase免费体验额度内。
- 免费额度用尽时提醒用户，不允许自动付费。

# 17. V1.0 验收标准

以下全部通过才可以认定V1.0完成：

1. 用户首次登录可以自动创建个人空间。
2. 可以创建家庭空间。
3. 其他3～4人可以通过邀请码加入。
4. 家庭成员无法访问非成员家庭数据。
5. 可以创建、编辑、删除菜谱。
6. 菜谱图片可以上传到云端。
7. 家庭成员可以查看共享菜谱图片。
8. 可以复制个人菜谱到家庭空间。
9. 可以计算菜谱成本。
10. 可以计算已知食材的营养。
11. 可以缩放菜谱份量。
12. 可以安排一周饮食计划。
13. 可以根据计划生成购物清单。
14. 可以管理多批次库存。
15. 可以记录实际烹饪过程。
16. 烹饪完成后可以按确认数量扣减库存。
17. 日历能够同时展示计划和实际记录。
18. 可以查看周榜、月榜、年榜。
19. 3～5台设备可以自动同步。
20. 关闭页面后实时监听连接能够释放。
21. 可以导出和恢复业务数据。
22. 断网时不会错误覆盖云端数据。
23. 家庭成员被移除后不能继续读取家庭数据。
24. 所有核心功能不依赖真实AI。
25. 资源消耗符合免费体验环境限制。
